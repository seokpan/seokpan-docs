# 2차 멘토링 정리 및 후속 적용

- **일자:** 2026-09-15
- **멘토:** 레드햇 김명환 멘토님
- **대상:** 석판팀 「石나가는 판단」 1차 프로젝트

## Summary

2차 멘토링에서는 남은 기간에 서비스를 실제로 시연할 수 있도록 애플리케이션 오류를 먼저 해결하고, 백업·복구와 관측 결과를 서비스에 미치는 영향까지 포함해 설명하는 방안이 논의됐다. 발표 구성과 팀 내 병목 지원에 관한 조언도 있었다.

| 멘토링 내용의 성격 | 주요 내용 | 석판팀 적용 판단 |
| --- | --- | --- |
| 마감 우선순위 | 애플리케이션 오류와 전체 사용자 흐름 | 경기 흐름을 우선 연결하고 재접속·경쟁 조건을 별도 검증 |
| 구현·설명 보완 | 이미지 검사, DB 백업 일정과 복구 범위 | 실제 공급 경로와 데이터별 복구 결과를 구분 |
| 운영 관점 확인 | 메트릭·로그·외부 알림과 서비스 지표 | 이미 확인한 수집·메일 수신과 남은 서비스 검증을 구분 |
| 일정·협업 조언 | 공개 인증서 교체의 우선순위를 낮추고 팀 병목 지원 | 이후 Windows PC 신뢰 문제를 해결하기 위해 인증서 교체를 별도 진행 |
| 발표·설명 조언 | 목표·결과, 선택 이유와 문제 해결 과정 | 실행 근거에 맞춰 설명 자료를 정리 |

1차 멘토링 이후의 항목별 변화는 [1차 문서의 비교표](MENTORING-01_2026-09-01.md#52-2026-09-15-비교표)에 있다.

## 1. 멘토링 내용을 읽는 기준

아래 ‘멘토 의견’은 멘토링 후 작성된 요약에 기록된 취지이고, ‘석판팀에 적용할 점’은 팀의 판단이다. 이미 진행 중이던 작업을 2차 멘토링에서 새로 시작한 것으로 취급하지 않는다. 실행 결과는 연결된 기록의 확인 범위에서 기술한다.

## 2. 멘토링 주요 내용

### 2.1 실제 사용자 흐름과 남은 오류

#### 멘토 의견

마감 전에 애플리케이션의 잔여 오류를 정리하고, 회원가입부터 게임 진행까지 실제 사용자 흐름을 보여주는 일에 집중하라는 조언이었다.

#### 석판팀에 적용할 점

기본 경기 흐름을 먼저 검증한다. 재접속·중복 처리·여러 Replica 사이의 경쟁과 게임 복구는 별개 시험으로 확인한다.

#### 이후 확인된 상태

[App #94](https://github.com/seokpan/seokpan-app/issues/94)에 9/18 Gateway Browser를 통한 로그인, 방 입장, 투표·착수, 결과·랭킹·채팅의 기본 흐름이 기록됐다. [App #112](https://github.com/seokpan/seokpan-app/issues/112)에는 일부 교차 Pod·재접속·경쟁 시험과 미완료 항목이 함께 남아 있다.

### 2.2 이미지 검사와 배포 경로

#### 멘토 의견

이미지 검사와 실행 이미지 구성을 실제 적용한 범위에서 설명하고, 보안 관련 조치를 구체적인 근거로 보여주라는 취지였다.

#### 석판팀에 적용할 점

기존 Jenkins·Harbor·GitOps 흐름을 유지한다. 이미지 검사, Digest 확인, 배포 승인과 실행 환경 검증을 각각 구분한다. 이미지 검사를 별도 클러스터 보안·컴플라이언스 검사 완료로 확대하지 않는다.

#### 이후 확인된 상태

[App PR #73](https://github.com/seokpan/seokpan-app/pull/73)은 이미지 검사 실패와 후보 이미지 Health 실패를 구분한다. Jenkins는 GitOps Promotion PR [#132](https://github.com/seokpan/seokpan-gitops/pull/132)·[#133](https://github.com/seokpan/seokpan-gitops/pull/133)·[#134](https://github.com/seokpan/seokpan-gitops/pull/134)를 생성했고 사람이 승인·병합했다. 변경 뒤 전체 기능 시험은 별도로 확인한다.

### 2.3 DB 백업과 서비스 영향

#### 멘토 의견

백업 때문에 서비스가 오래 멈추는 일을 피하도록 백업 주기, 소요 시간, 서비스 영향과 복구 경로를 함께 고려하라는 조언이었다.

#### 석판팀에 적용할 점

이미 진행 중이던 MariaDB 백업 체인과 저장 위치 정리를 이어간다. 학원 PC가 주말에 종료되는 운영 조건에 맞게 백업 일정을 조정하고, 실제 정기 실행의 안정성과 복원 결과를 각각 확인한다. DB 복구를 서비스 전체 복구로 확대하지 않는다.

#### 이후 확인된 상태

[Infra #144](https://github.com/seokpan/seokpan-infra/issues/144)는 주말 VM 종료에 맞춰 Full을 수요일 14:00, Incremental을 월·화·목·금 02:00으로 변경했다. [#129 실행 기록](https://github.com/seokpan/seokpan-infra/issues/129#issuecomment-5690785550)에서는 9/15 새벽 정기 실행이 NFS 마운트 문제로 중단돼, 복구 후 수동 재실행으로 Full 승격을 검증했다고 구분한다.

[DB DR 실행 기록](https://github.com/seokpan/seokpan-infra/issues/194#issuecomment-5693088516)은 격리 Full-only 복원 **27.376초**, 단일 DB 접근 재개 **1분 29초**, 두 서버 복제 정상화 **4분**을 서로 다른 완료 시점으로 기록한다. Incremental 이후 주입한 미백업 데이터 **3건 손실**과 `backup_restore_role=master` 조건 누락으로 인한 fatal 오류(데이터 영향 없음)도 보고됐다. 이 수치는 실제 서비스 전체 복구 시간이나 정기 백업의 무중단 운영 측정값이 아니다.

### 2.4 etcd와 서비스 데이터의 복구 범위

#### 멘토 의견

etcd Snapshot은 Kubernetes 객체 상태를 대상으로 한다. DB·Redis와 애플리케이션 데이터의 복구를 별도로 고려하라는 조언이었다.

#### 석판팀에 적용할 점

컨트롤 플레인 멤버 복구, 격리 etcd Restore, DB 복원, Redis와 게임 상태 복구를 서로 다른 검증 대상으로 둔다.

#### 이후 확인된 상태

[etcd 후속 PR #191](https://github.com/seokpan/seokpan-infra/pull/191)은 격리 Restore **52초**, 3/3 quorum과 API·객체 목록 확인을 기록한다. Snapshot 생성·전송 및 서비스 전체 재시작 시간은 포함하지 않는다. [Redis DR 기록](https://github.com/seokpan/seokpan-infra/issues/115)은 격리 synthetic 환경의 AOF 재생·손상 파일 처리·Board 재구성 시험을 PASS로 기록한다. 운영 게임의 활성 Session·Room·Vote 전체 자동 복구와는 별개이며, 9/27 점검에서는 실행 원본으로 재추적할 수 있는 Evidence 요약 값이 비어 있다고 확인했다.

### 2.5 관측과 외부 알림

#### 멘토 의견

메트릭·로그·알림 구성을 긍정적으로 보면서, 실제 서비스의 상태를 판단할 수 있는 지표까지 확인하라는 취지였다.

#### 석판팀에 적용할 점

테스트 메일 수신, 외부 VM 메트릭, 애플리케이션 지표와 Dashboard의 실제 데이터 표시를 각각 확인한다.

#### 이후 확인된 상태

[Observability 담당 검증 문서](../12_MVP_검증·측정_계획/12_MVP_검증·측정_계획_Delivery_Observability_최유준.md)는 외부 VM node-exporter **7/7**, MariaDB **2/2**, Harbor **1/1** Target UP과 firing·resolved 팀 메일 수신을 기록한다. Cluster·외부 VM·MariaDB·서비스 Dashboard **4종의 Provisioning과 관점 분리·Query 정합도 PASS**로 기록했다. [Backend 지표 조회](https://github.com/seokpan/seokpan-gitops/issues/91)와 [Node journal 로그 조회](https://github.com/seokpan/seokpan-gitops/issues/98#issuecomment-5677873076)는 각각 별도 확인 결과다. 프로젝트 전용 Alert Rule은 Deferred이며, 모든 Panel에서 개별 장애 상태의 표시를 검증했다는 뜻은 아니다.

### 2.6 인증서 변경의 우선순위

#### 멘토 의견

발표 준비 기간에 공개 인증서로 교체하는 작업보다 서비스 오류와 시연 준비에 시간을 쓰라는 조언이었다.

#### 석판팀에 적용할 점

공개 인증서 교체는 기존 검토 과제였다. 후속 작업에서는 Windows PC의 인증서 신뢰 문제를 해결하기 위해 Gateway 인증서 전환을 진행했다. 이는 2차 멘토가 인증서 교체를 우선 지시했다는 뜻은 아니다.

#### 이후 확인된 상태

[Infra #188](https://github.com/seokpan/seokpan-infra/issues/188#issuecomment-5690307789)에 Let's Encrypt Production 인증서의 Gateway 적용과 Windows Browser·팀원 PC 수용 결과가 기록됐다. 자동 갱신은 구현하지 않았다.

### 2.7 발표 설명과 팀 협업

#### 멘토 의견

목표와 달성 결과를 먼저 전하고 기술 선택 이유와 문제 해결 과정을 도해·측정 근거로 설명하라는 조언이었다. 자신의 작업을 마친 팀원은 다른 팀원의 급한 문제를 지원하라는 운영 조언도 있었다.

#### 석판팀에 적용할 점

실제 선택·구현·검증한 내용을 설명에 사용하고 담당자가 근거와 한계를 이해하도록 확인한다. 협업 성과는 개인 기여 비율로 환산하지 않고 작업과 인계 기록으로 확인한다.
