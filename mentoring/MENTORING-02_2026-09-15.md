## 1. 주요 논의

| 인증서 | 발표 일정에서 공개 인증서 교체의 우선순위는 낮게 둔다. | 사용자 PC의 인증서 신뢰 확인이 남아 있었다. 이후 실행 결과가 기록됐다. |

## 3. 발표 이후 확인된 결과

### 서비스와 배포

- 9/18 [App #94](https://github.com/seokpan/seokpan-app/issues/94)에 Gateway Browser로 로그인부터 방 입장, 투표·착수, 결과·랭킹·채팅까지 진행한 기본 사용자 흐름이 기록됐다.
- 이미지 검사·빌드와 Harbor Digest 확인 뒤 Jenkins가 GitOps Promotion PR [#132](https://github.com/seokpan/seokpan-gitops/pull/132), [#133](https://github.com/seokpan/seokpan-gitops/pull/133), [#134](https://github.com/seokpan/seokpan-gitops/pull/134)를 자동 생성했고, 사람이 승인·병합했다. #134는 **9/23 00:20 KST** 병합됐다. 각 변경 후의 전체 기능 시험은 별도로 확인해야 한다.
- [Infra #188](https://github.com/seokpan/seokpan-infra/issues/188)에 Gateway 인증서 발급·적용과 사용자 PC 수용 결과가 남아 있다. 인증서 갱신 절차는 수동이다.
- [GitOps #109](https://github.com/seokpan/seokpan-gitops/issues/109)는 실제 배포 이미지와 동일한 Digest의 Harness에서 애플리케이션 오류를 격리하고 Alloy → Loki 조회까지 확인했다. 운영 DB·Redis에는 장애를 주입하지 않았다. [App #112](https://github.com/seokpan/seokpan-app/issues/112)는 이미 수행한 F11과 후속 검증을 구분한다.

[Backend 설정](https://github.com/seokpan/seokpan-app/blob/b774a4036d6b5714c6e370ddd46321caaf2ba952/backend/src/seokpan/settings.py)과 [GitOps ConfigMap](https://github.com/seokpan/seokpan-gitops/blob/b79a2e052381553297df5e0f4a29a99ecf09cc60/apps/backend/configmap.yaml) 기준 게임 생명주기 모드는 `legacy`다. `captured` 구현은 운영 활성화 결과에 포함되지 않는다. 배포 되돌리기 시험에서는 가용 Replica가 **2 → 1 → 2**로 변했다. [GitOps #57 실행 기록](https://github.com/seokpan/seokpan-gitops/issues/57#issuecomment-5723675021)

### 자동화·관측

- [Infra PR #184](https://github.com/seokpan/seokpan-infra/pull/184)의 공용 안전 실행기와 일부 실행 결과가 반영됐다. 정태훈의 setup·inspect는 통과했고 `kubernetes_validate.yml`은 Check Mode에서 중단돼 Apply는 수행되지 않았다. 전체 VM Clean Build 성공 기록은 없다.
- [최종 담당 검증 문서](../12_MVP_검증·측정_계획/12_MVP_검증·측정_계획_Delivery_Observability_최유준.md)는 외부 VM node-exporter **7/7**, MariaDB **2/2**, Harbor **1/1** Target UP과 팀 메일 수신을 기록한다. [Backend Metric 조회](https://github.com/seokpan/seokpan-gitops/issues/91)와 [5개 Node journal의 Loki 조회](https://github.com/seokpan/seokpan-gitops/issues/98#issuecomment-5677873076)도 각각 확인됐다. Dashboard 구성과 모든 Panel의 실제 데이터 확인은 범위가 다르다.

## 4. 남은 검증

- [App #112](https://github.com/seokpan/seokpan-app/issues/112): 9/28 기록에는 서로 다른 Pod의 WebSocket 교체, 이전 연결의 늦은 종료 처리, 10초 유예 안의 재접속과 일부 2 Replica 경쟁 시험이 완료로 표시돼 있다. Redis 연결 세대의 최종 수렴, 최초 연결·1011 오류 이후 상태, 재접속 중 Leave, 실제 Provider 경쟁, 게임 복구 및 성능 측정은 남아 있다.
- [Kubernetes/Application 검증표](../12_MVP_검증·측정_계획/12_MVP_검증·측정_계획_Kubernetes_Application_Integration_정태훈.md): 기본 게임 흐름의 후속 실행 결과와 남아 있는 `In Progress` 항목의 범위 정합화.
- HPA·부하 처리량과 지연 비교, 전체 신규 구축시간의 동일 조건 비교, 전체 서비스 DR. 별도 Cluster Compliance, 통합 SSO와 상시 Secondary Cluster도 완료 결과에 포함되지 않는다.

9/26 [Application Roadmap #3](https://github.com/seokpan/seokpan-app/issues/3)의 종료는 구현 결과와 남은 검증의 분류·인계 기록이다. 1차 멘토링의 항목별 전후 상태는 [9/15 비교표](MENTORING-01_2026-09-01.md#52-2026-09-15-비교표)에 있다.
