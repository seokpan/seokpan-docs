# TS-001 — Calico Pod CIDR 후보 설정이 프로젝트 사설망과 중첩

## 문제 개요

GitHub 저장소(Repository) 안에 서로 다른 Calico Custom Resource 후보가 동시에 존재했다.

- 실제 프로젝트 클러스터(Live Cluster) 기준: `10.244.0.0/16`
- 다른 후보 파일: `192.168.0.0/16`

문제는 `192.168.0.0/16`이 프로젝트의 실제 사설망인 `192.168.51.0/24`~`192.168.54.0/24`를 포함한다는 점이었다.

## 영향

발견 시점의 실제 Kubernetes 클러스터는 `10.244.0.0/16`을 사용하고 있어 정상 동작하고 있었다. 즉 이미 발생한 서비스 장애는 아니었다.

하지만 향후 Calico 설치 자동화에서 잘못된 후보 파일을 적용하면 Pod CIDR과 서버 사설망이 중첩되어 라우팅·통신 장애가 발생할 수 있었다.

## 원인 분석

문서와 자동화 후보를 정리하는 과정에서 서로 다른 시점에 작성된 Calico 설정이 함께 남아 있었고, 실제 클러스터 설정과 적용 후보 파일을 분리해서 검증하지 않으면 잘못된 CIDR을 선택할 수 있는 상태였다.

## 조치

- 프로젝트 Kubernetes Pod CIDR을 `10.244.0.0/16`으로 확정
- `192.168.0.0/16` 후보 설정 제거
- Calico VXLAN 설정과 실제 클러스터 IPPool을 다시 대조
- BGP 비활성화, VXLAN CrossSubnet, MTU 1450, NAT 설정을 현재 프로젝트 기준으로 정리

## 검증

- 실제 Calico IPPool: `10.244.0.0/16`
- Kubernetes Node/Pod 통신 정상
- NetworkPolicy 기능 유지
- 프로젝트 사설망 `192.168.51.0/24`~`192.168.54.0/24`와 Pod CIDR 비중첩 확인

## Before → After

```text
Before
서로 다른 Pod CIDR 후보 공존
→ 잘못된 후보 적용 시 사설망 중첩 가능

After
10.244.0.0/16 단일 기준
→ 실제 클러스터와 자동화 후보 정합화
```
