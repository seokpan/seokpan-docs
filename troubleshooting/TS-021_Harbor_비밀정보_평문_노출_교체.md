# TS-021 — Harbor 관리용 비밀정보가 평문으로 노출된 사실이 확인되어 자격증명 교체가 필요한 보안 후속 문제

> 이 문서는 「石나가는 판단」 프로젝트에서 실제로 발생하거나 검증 과정에서 발견된 문제를 기록한 개별 트러블슈팅 보고서입니다. 링크를 열지 않아도 사건의 배경, 영향, 원인, 조치, 검증 결과와 남은 사항을 이해할 수 있도록 작성합니다.

## 문제 개요

Harbor 내부 CA와 BuildKit 신뢰 구성을 진행하던 PR #87의 영향 및 주의사항에서, **Harbor 관련 관리용 비밀정보 3종이 이전 대화 과정에서 평문으로 노출된 적이 있어 교체가 필요하다**는 사실이 명시됐다.

문서에는 실제 비밀값을 다시 기록하지 않는다. 확인된 범위는 다음 종류의 자격증명이다.

- Harbor 관리자 계정 관련 비밀번호
- Harbor가 사용하는 데이터베이스 관련 비밀번호
- Harbor Robot Account 관련 Secret

이 문제는 GitHub 저장소(Repository)에 평문 Secret이 Commit됐다는 의미로 확인된 것은 아니다. 현재 근거가 직접 확인하는 것은 **대화 과정에서의 평문 노출 사실과 그에 따른 자격증명 교체 필요성**이다. 따라서 노출 경로나 값을 추정해 확대하지 않고 확인된 범위만 기록한다.

## 영향

비밀정보는 한 번 평문으로 노출되면 이후 해당 값이 더 이상 안전하다고 전제할 수 없다. 실제 악용 여부가 확인되지 않았더라도, 기존 값을 계속 사용하는 것은 불필요한 보안 위험을 남긴다.

특히 Harbor는 Jenkins가 이미지를 Push하고 Kubernetes가 이미지를 Pull하는 Registry이므로 관련 자격증명 문제가 남으면 다음 영역에 영향을 줄 수 있다.

- Harbor 관리자 작업
- Jenkins → Harbor 이미지 Push
- Robot Account를 사용하는 자동화
- Harbor 설정 또는 데이터베이스 접근

## 원인

현재 GitHub 근거만으로 노출이 발생한 구체적인 대화 단계나 입력 경로를 확정할 수는 없다. 확인 가능한 원인은 **비밀정보를 대화나 작업 과정에서 평문으로 취급할 수 있었던 운영 절차상의 문제**다.

따라서 이 사례에서는 원인을 특정 개인의 실수로 단정하지 않고 다음과 같이 기록한다.

- Secret을 전달·검증하는 과정에서 평문 취급을 허용한 절차
- 노출 후 즉시 폐기·교체하는 절차가 아직 완료되지 않음
- Harbor 관련 Secret의 수명주기 관리가 작업 흐름과 완전히 분리되지 않음

## 현재 조치 상태

PR #87에서는 이 문제를 CA Trust 변경과 **별개의 후속 작업**으로 분리한다고 명시했다. CA Private Key를 `cicd` Namespace에 전달하지 않고 공개 CA 인증서만 사용하도록 한 현재 변경과도 별개다.

현재 확인 가능한 GitHub 기록에서는 해당 3종 자격증명의 **실제 교체 완료 근거는 아직 확인되지 않았다.** 따라서 해결로 기록하지 않는다.

필요한 후속 조치는 다음과 같다.

1. 노출된 것으로 확인된 기존 자격증명을 폐기하거나 교체한다.
2. Harbor 설정, Ansible Vault, Jenkins/Robot Account 등 실제 소비 위치를 새 값과 맞춘다.
3. 기존 값으로 인증이 더 이상 되지 않는지 확인한다.
4. 새 값으로 Harbor 관리·Robot Account·Jenkins Push 경로가 정상 동작하는지 재검증한다.
5. 검증 로그와 문서에는 실제 Secret 값을 남기지 않는다.

## 검증 완료 기준

이 사례는 다음 항목이 모두 확인되어야 **해결**로 전환한다.

- 해당 자격증명 3종의 교체 완료
- 구 자격증명 사용 불가 확인
- 새 자격증명으로 필요한 Harbor 기능 정상 동작
- GitHub 저장소와 프로젝트 문서에 평문 Secret이 남지 않았는지 재확인
- 필요한 경우 Jenkins/Robot Account 연동 회귀검증 완료

## 담당 역할 및 영향

- **최유준:** Harbor와 CI/CD 영역에서 자격증명 교체 및 연동 재검증 주 담당
- **정태훈:** 애플리케이션 이미지를 Harbor에서 사용하므로 이미지 Pull 및 배포 경로 회귀 여부 확인
- **전체 팀:** Secret을 Issue·PR·대화·문서에 평문으로 재기록하지 않는 운영 규칙 준수
